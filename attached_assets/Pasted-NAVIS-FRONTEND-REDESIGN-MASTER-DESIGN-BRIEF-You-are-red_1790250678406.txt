NAVIS FRONTEND REDESIGN — MASTER DESIGN BRIEF

You are redesigning the EXISTING NAVIS application.

NAVIS is an existing full-stack Solana/Web3 product. This is NOT a request to create a new static prototype from scratch.

Your job is to improve the visual design, typography, spacing, color system, UX, responsiveness and overall product quality while preserving all existing functionality.

IMPORTANT:
Do not break backend logic, APIs, database, authentication, wallet sessions, Atlas, market data, PreStocks, ClawPump, Meteora, Pyth, transaction preparation, proof receipts or existing routes.

Do not invent functionality.

Do not create fake data.

Do not create fake integration statuses.

Do not create fake transaction signatures.

Do not claim something is live if it is only simulated, prepared, devnet, blocked or planned.

==================================================
7. TYPOGRAPHY — REDESIGN IT
==================================================

Do NOT simply preserve the existing typography.

Audit:
- font family
- weights
- type scale
- heading hierarchy
- body text
- labels
- metadata
- buttons
- numerical values
- tables
- docs
- code
- line-height
- letter-spacing

Create a deliberate NAVIS typography system.

Use clear hierarchy for:
- Display
- H1
- H2
- H3
- body
- secondary text
- labels
- captions
- numerical values
- technical data

Financial numbers must be easy to scan.

Do not use enormous headings everywhere.

Do not use generic typography without a reason.

==================================================
8. SPACING — REDESIGN IT
==================================================

Do NOT preserve arbitrary existing margins/padding.

Establish a coherent spacing scale.

Audit:
- page padding
- section spacing
- card padding
- dashboard spacing
- navigation spacing
- table density
- form spacing
- modal spacing
- docs spacing
- footer spacing
- mobile spacing

Create consistent visual rhythm.

Related things should be close.

Unrelated things should have larger separation.

Avoid both:
- cramped layouts
- excessive empty space

==================================================
9. COLOR PALETTE — REDESIGN IT
==================================================

Do NOT merely recolor individual components.

Create a complete semantic color system.

Define:

- background
- elevated surface
- muted surface
- border
- strong border
- primary text
- secondary text
- muted text
- disabled text
- accent
- accent hover
- accent active
- success
- warning
- danger
- info

The palette should feel appropriate for serious financial/onchain software.

Avoid generic:
- black + purple AI styling
- rainbow colors
- neon overload
- excessive gradients
- random accent colors
- low-contrast text

Color should communicate hierarchy and state, not decorate every component.

==================================================
10. ANTI-UI-SLOP RULE
==================================================

Avoid generic AI-generated combinations such as:

- giant hero typography
- three identical cards
- excessive pills
- excessive rounded rectangles
- fake bento grids
- terminal windows
- sparkle icons
- animated arrows everywhere
- floating radial orbs
- dot grids
- huge icons
- rainbow gradients
- fake testimonials
- fake statistics
- fake logos
- excessive glassmorphism
- excessive glow
- hover animations everywhere

This does not mean every one of these is forbidden individually.

Use an element only if it improves NAVIS.
